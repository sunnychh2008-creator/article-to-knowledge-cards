# make-knowledge-cards

把一篇文章或本地 Markdown/TXT 文件，压缩成 5~8 张能记住、能复习的知识卡片。

## 1. 解决什么问题

读完一篇文章，记住了什么？通常是零散的几句话，而不是能复述的知识结构。手动做卡片又有两个麻烦：

**抽不出重点。** 文章里的例子、背景、作者经历和核心观点混在一起，划重点时容易把铺垫当结论。

**一定会编造。** 手动整理时，为了让卡片「讲得通」，很容易不自觉补上原文没有的因果、数据和场景。这类内容一旦混进知识库，后面就分不清哪些是原文的、哪些是自己想的。

这个 Skill 把这两件事交给规则约束：**只提取真正重要的知识，宁可少出也不注水；所有内容必须能在原文找到出处，包括「简明解释」栏。**

适用于知识库整理、读书笔记、文章消化。

## 2. 主要功能

| 功能 | 说明 |
| --- | --- |
| 卡片化文章 | 5~8 张，每张含标题、核心知识、简明解释、例子或自测问题 |
| 两种输入 | 粘贴正文，或给本地 `.md` / `.txt` 文件路径 |
| 可选写文件 | 指定路径时输出到 `.md` 文件 |
| 语言跟随原文 | 中文原文出中文卡，英文原文出英文卡 |
| 判断信息量 | 不足 5 张时减少数量并说明原因，不硬凑 |

五条内容规则：

1. **只提取真正重要的知识** —— 次要细节、个人经历、动机铺垫一律剔除
2. **一卡一知识点** —— 多个主张塞一张卡就拆开
3. **删除重复内容** —— 按语义去重，不按字面
4. **严禁编造** —— 原文没有的话一个字都不加
5. **数量不足就说不足** —— 不为凑满 5 张而拆分或重复

### 明确不支持

| 输入/需求 | 原因 |
| --- | --- |
| 网页链接 | 不做抓取。复制正文粘贴过来 |
| PDF / Word / PPT | 不做解析。复制正文粘贴过来 |
| 导出 Anki 等闪卡 App 格式 | 只输出 Markdown |
| 图形界面 | 纯文本产出 |

## 3. 安装方法

Skill 是一个目录，把它放进 Skill 搜索路径即可，不需要执行安装脚本。

**用户级安装**（推荐，所有项目可用）：

```bash
# Windows
copy -r skills\make-knowledge-cards "$USERPROFILE\.workbuddy\skills\"

# macOS / Linux
cp -r skills/make-knowledge-cards ~/.workbuddy/skills/
```

**项目级安装**（只在本项目可用，提交仓库时推荐）：

```bash
mkdir -p .workbuddy/skills
cp -r skills/make-knowledge-cards .workbuddy/skills/
```

安装后重新打开会话即可生效。可用 `/make-knowledge-cards` 直接调用。

## 4. 使用方法

**粘贴文章：**

```
把下面这篇文章做成知识卡片：

<粘贴正文>
```

**给文件路径：**

```
把 ~/notes/缓存设计.md 转成知识卡片
```

只支持 `.md` 和 `.txt`。路径不存在或扩展名不对会提示确认。

**指定输出文件：**

```
把 ~/notes/缓存设计.md 转成知识卡片，写到 ~/notes/缓存设计-卡片.md
```

不指定路径时默认写入同级目录的 `知识卡片.md`。

**超过 2 万字的文件**会先提示是否分段处理，不静默截断。

## 5. 输入输出示例

### 输入

一段清单式短文：

```markdown
## 数据

- 新增字段有默认值，能兼容历史数据
- 涉及金额的字段精度统一，不用 float
- 有回滚方案，且回滚脚本已经实际跑过一遍，不是"理论上可回滚"
```

### 输出

````markdown
已生成 3 张知识卡片。原文是清单式内容。

### 卡片 1｜新增字段要有默认值以兼容历史数据

**核心知识**
新增字段必须有默认值，保证能兼容历史数据。

**简明解释**
历史数据里没有这个字段，如果没有默认值，读取时就会拿到空值甚至报错。有默认值，老数据也能按新结构正常参与计算。

**例子 / 自测问题**
自测问题：新增字段为什么要给默认值？
答案：为了兼容历史数据——老数据没有该字段，无默认值会导致读取异常。

### 卡片 2｜金额字段不用 float

**核心知识**
涉及金额的字段精度要统一，不使用 float。

**简明解释**
浮点数无法精确表示十进制小数，金额运算会出现精度丢失。精度不统一还会在不同环节产生对不上的结果。

**例子 / 自测问题**
自测问题：金额字段为什么不用 float？
答案：浮点数无法精确表示十进制小数，金额运算会精度丢失；精度不统一还会导致结果对不上。

### 卡片 3｜回滚脚本要实际跑过

**核心知识**
必须有回滚方案，且回滚脚本要实际跑过一遍，不能只是"理论上可回滚"。

**简明解释**
没验证过的回滚方案等于没有。真到需要回滚的时候才会发现脚本有问题，那正是最不该出问题的时刻。

**例子 / 自测问题**
原文例子：清单明确要求回滚脚本"已经实际跑过一遍"，而不是"理论上可回滚"。

原文信息量有限，仅够 3 张卡片，未凑满 5 张。
````

注意最后一行：数量不足时会**明确说明**，而不是硬凑到 5 张。

## 卡片结构

每张卡固定三个字段：

- **核心知识** —— 忠于原文，保留原文的限定条件、数字、术语
- **简明解释** —— 换措辞讲透为什么，但不补原文没有的因果机制
- **例子 / 自测问题** —— 原文例子信息量足就用例子，否则出自测问题加答案，答案必须能从原文推出

## 开发与验证

`quick_validate.py` 不在本仓库内，需从 skill-creator 取得：

```bash
# 依赖
pip install pyyaml

# 验证（路径按实际 skill-creator 位置调整）
python <skill-creator路径>/scripts/quick_validate.py skills/make-knowledge-cards
```

预期输出 `Skill is valid!`，退出码 0。

验证只检查 frontmatter 结构（`name` / `description` 格式、命名规范、长度限制），**不检查规则内容质量**——后者靠 `tests/` 目录下的四类样例人工过一遍。
