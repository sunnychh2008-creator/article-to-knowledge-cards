# 知识卡片生成

把一篇文章或本地 Markdown/TXT 文件，转成 5~8 张可记忆、可复习的知识卡片。

## 何时使用

用户提供了以下任一输入，并要求提炼知识点/做成卡片：

- 直接粘贴的文章正文
- 本地 `.md` 或 `.txt` 文件路径
- 明确说「拆解要点」「提炼知识点」「卡片化」「转成记忆卡片」

## 明确不支持

遇到以下情况，直接说明不支持并给出替代建议，**不要尝试绕过**：

| 用户要求                     | 回应                                        |
| ------------------------ | ----------------------------------------- |
| 给 URL / 链接要转卡片           | 本 Skill 不做网页抓取。建议用户把正文粘贴过来，或先用抓取工具拿到正文再回来 |
| 给 PDF / DOCX / PPTX 要转卡片 | 本 Skill 不做 PDF 或 Office 解析。建议用户复制正文粘贴过来   |
| 导出 Anki / 闪卡 App 格式      | 本 Skill 只输出 Markdown 卡片。需要导入格式请自行转换       |
| 要图形界面 / 网页版工具            | 本 Skill 是纯文本产出，没有界面                       |

## 工作流程

### 第 1 步：确认输入形态

- **粘贴正文** → 直接进入第 2 步。
- **文件路径** → 用 Read 工具读取该 `.md` / `.txt` 文件。若路径不存在或扩展名不对，说明情况并请用户确认。
- 读取后如果发现内容超过约 20000 字，先告知用户并询问是否分段处理，不要静默截断。

### 第 2 步：判断信息是否足够

先估一下这篇文章能撑起几张卡：

| 文章情况              | 可支撑卡片数          | 处理方式                  |
| ----------------- | --------------- | --------------------- |
| 少于 300 字的短文       | 1~3 张           | 照实给，少于 5 张是正常的        |
| 单一论点的短评           | 2~4 张           | 只出这个论点及其支撑，不要拆出周边话题   |
| 结构清晰的长文           | 5~8 张           | 正常范围                  |
| 列表型内容（清单、步骤、要点罗列） | 等于列表中「有信息量」的条目数 | 每条一个候选，剔除无信息量的条目      |
| 论述型内容（长篇论证、综述）    | 5~8 张           | 优先抽论点与关键机制，案例与背景归入例子里 |

**信息不足时减少卡片数量，并在输出末尾用一句话说明原因**（例如「原文信息量有限，仅够 4 张卡片，未凑满 5 张」）。绝不为了凑数把一句话拆成三张，或把同一概念换个说法重复三遍。

### 第 3 步：抽取候选知识点

通读全文，列出候选知识点，然后逐条过两道筛子。

**筛子一：重要性** —— 满足任意一条才保留：

- 不知道它就会理解错全文主旨
- 它是全文结论成立的必要前提
- 它是作者明确给出的方法、原则、机制或因果关系
- 它能直接指导读者的判断或行动

不满足的一律剔除。典型该剔除的：作者的寒暄与个人经历、背景故事、动机铺垫、举例用的闲笔、情绪化的形容词、重复强调的同一件事、不影响结论的次要细节。

**清单型内容专用判据** —— 清单、步骤、要点罗列类文章，另加一问：

> 这个条目是**可迁移的原则**，还是**一次性的动作**？

- 可迁移的原则：「权限校验必须做在服务端，不能只在前端隐藏」「回滚脚本要实际跑过，不是理论上可回滚」→ 保留。
- 一次性的动作：「变更内容同步给客服和运营」—— 只在这份清单里成立，没有可迁移的方法论内核 → 剔除。

若剔除后卡片数不足 5 张，那是原文的正确结果，不是需要弥补的缺口。

**作者经历类叙述** —— 默认作为例子的素材，不单独成卡。只有当这段经历本身就是作者论证的核心证据时，才值得独立成卡。

**结构信号不是知识点** —— 以下属于文章骨架，出卡时一律跳过：

- 小节标题与序号（「误区一」「第一点」「Part 2」）
- 自问自问与设问句（「那么这个理由成立吗？」）
- 过渡句与转折标记（「接下来看看」「但真正的问题是」）
- 主题句在文末的重复陈述

**标题必须重写** —— 不得照抄原文小节标题或段落首句。小节标题是目录（"误区二：用固定过期时间代替失效策略"），知识点标题是可独立理解的判断（"统一过期时间是缓存雪崩的直接成因"）。判断方法：把标题单独拿出来给一个没读过原文的人看，他能不能懂这是在讲什么。

**筛子二：单一知识点** —— 一张卡片只能承载一个主张。检查每条候选：

- 句子里出现「而且 / 同时 / 另外 / 以及 / 除此之外」，说明塞了多个主张 → 拆开，或只留最重要的一半。
- 一张卡片读下来需要读者同时记住两件事 → 太满，拆。
- 一张卡片只有三五个字的信息量 → 太薄，并入相邻卡片或丢弃。
- 同一小节内可以拆出多张卡，但必须来自**不同层次**（现象 vs 判断标准 vs 后果），而不是同一层次的并列展开。

**「单一知识点」的唯一例外**：同一条件的正反面表述合并为一张卡，不算超载。例如「适用场景是 A、B、C」与「前提不成立时该选 D」放在一张卡里——它们是同一判断的两面，拆开必然重复。

### 第 4 步：去重

对候选列表做两两比对，**按语义判断，不按字面**：

- 两张卡讲的是同一个道理的不同表述 → 合并成一张，用最准确的表述。
- 两条是同一知识点的「是什么」和「为什么」→ 可以拆成两张，前提是各自独立成立；否则合并。
- 同一概念在原文出现三次 → 只出一次，在例子里可以引用后文的补充说明。

去重后再确定最终卡片数量。

### 第 5 步：写卡片

严格使用下面的模板，一张一张写：

```markdown
### 卡片 N｜<标题>

**核心知识**
<一到三句话讲清这个知识点本身。原文怎么说就怎么说，不要升级成更普遍的规律。>

**简明解释**
<用自己的话讲一遍为什么是这样，面向不了解该领域的人。2~4 句。>

**例子 / 自测问题**
<二选一，见下方规则。>
```

字段规则：

- **标题**：中文 6~20 字，英文 4~10 词。必须能独立看懂，不出现「浅谈」「详解」这类空词，也不照抄原文小节标题。
- **核心知识**：忠于原文。原文的限定条件、适用范围、数字、术语必须保留。原文没说的不要补。
- **简明解释**：可以换措辞，但不能换结论。这一栏是给读者搭脚手架，不是补充新知识。

  **搭脚手架允许**：换一种说法把原文的因果关系讲透，说明「为什么原文这么说」，帮读者理解前置概念。

  **搭脚手架禁止**：补原文没给的因果机制、数据、场景。原文只说结论时，解释栏只能把这个结论讲清楚，不能解释「为什么这个结论在别的场景也成立」。
- **例子 / 自测问题** —— 二选一，取决于原文的例子质量：
  - **原文有信息量足的例子** → 用原文的例子。可以为清晰起见简化或换措辞，但**不得改动其中的数字、名称、结论**。
  - **原文的例子质量差**（只是随口一提、过于简略、或根本只是现象描述）→ 出自测问题，不硬撑。
  - **原文没有例子** → 出一个自测问题（问句形式），紧跟一行答案。答案必须能从原文推出，原文推不出就不要出这道题。

  **自测问题的优先级**：判断型 > 原因型 > 复述型。
  - 判断型：「只在前端隐藏按钮够吗？」「下面哪个查询适合进缓存？」—— 有复习价值。
  - 原因型：「为什么说缓存只会放大不一致而不是解决它？」—— 可以。
  - 复述型：「周报应该服务谁？」—— 只做填空，价值低。能不出就不出。

### 第 6 步：自检

逐条核对，任何一条不通过就回去改：

1. 每张卡是不是只有一个知识点？（正反面表述合并属允许例外）
2. 有没有哪句话是原文里找不到的？（编造是最严重的错误，宁可少写一句）特别检查「简明解释」栏——最容易在这里越界。
3. 有没有照抄原文小节标题或段落首句当卡片标题？
4. 有没有把自问自答、过渡句、序号标题当成知识点？
5. 卡片之间有没有重复？
6. 有没有该删的次要细节混进来？
7. 数量是否落在 5~8 张，或已说明为什么更少？

## 常见失败模式速查

| 症状              | 病因                 | 处理                      |
| --------------- | ------------------ | ----------------------- |
| 卡片标题是「误区一」「第一点」 | 把文章骨架当知识点          | 按「标题必须重写」重写             |
| 卡片数超过 8 张       | 清单条目没做「原则 vs 动作」筛选 | 剔除一次性的动作条目              |
| 卡片数不到 5 张       | 硬凑会重复或编造           | 检查是否把正反面拆开了；确实不够就照实给并说明 |
| 某张卡读下来是两件事      | 塞了多个主张             | 拆开，或只留最重要的一半            |
| 解释栏出现原文没有的因果    | 搭脚手架越界             | 删掉原文没说的部分               |
| 例子里的数字很具体但原文没有  | 编造                 | 换成自测问题                  |

## 输出格式

先输出一段不超过 3 行的开场：说明生成了几张卡、原文是什么类型的文章。然后是全部卡片，Markdown 格式，卡片之间空一行。

结尾如果卡片数少于 5 张，加一句说明原因。

如果用户明确要求写入文件，把同样的 Markdown 内容写入用户指定的 `.md` 路径（未指定则同级目录 `知识卡片.md`），写完告知路径。

## 卡片语言

跟随原文语言。中文原文出中文卡片，英文原文出英文卡片；中英混杂时以主体语言为准，术语保留原文写法。

## 反面案例

**该删的次要细节**

原文：「上周和客户开会时他提到，2019 年那版方案我们当时评估了三种架构，最后选了 B，因为团队熟悉 Node.js……」

错误做法：把「2019 年评估过三种架构」「团队熟悉 Node.js」各出一张卡。

正确做法：这些是背景与例子的铺垫。除非客户的核心方法论就在其中，否则不单独成卡，需要时作为例子的素材。

**一张卡塞两个知识点**

错误做法：标题「缓存失效的两种策略」，核心知识同时讲「时间过期」和「容量淘汰」。

正确做法：拆成两张卡，各自独立成立；或者只保留原文真正重点讲的那一种。

**凑数**

原文只支撑 4 张卡。错误做法：把结论拆成「结论是什么」+「结论意味着什么」+「结论怎么用」三张。

正确做法：给 4 张，并说明「原文信息量有限，仅够 4 张」。

**编造**

原文只说「定期清理无用条目可以降低延迟」。

错误做法：例子写「某电商系统缓存 10 万条，清理后 P99 从 800ms 降到 120ms」。

正确做法：出成自测问题 ——「为什么要定期清理无用条目？」答案只写原文给出的那一句。

**照抄小节标题**

原文小节标题是「误区二：用固定的过期时间代替失效策略」。

错误做法：直接拿它当卡片标题。

正确做法：重写为「统一过期时间是缓存雪崩的直接成因」—— 小节标题描述的是文章结构，知识点标题描述的是知识本身。

**清单里的一次性动作**

原文清单有一条「变更内容同步给客服和运营」。

错误做法：给它单独出一张卡，卡片数被迫凑到 11 张。

正确做法：剔除。它没有可迁移的原则内核，保留只会稀释卡片价值。

**搭脚手架越界**

原文说「会议记录只需要：决定了什么、谁负责、什么时候之前完成」。

错误做法：解释栏写「缺任何一项决议都推不动，所以这三项构成了决议落地的最小闭环」——「推不动」「最小闭环」都是原文没说的因果机制。

正确做法：只讲清这三项各自对应什么，用读者已知的常识连接，不引入原文之外的新论断。
